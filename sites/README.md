# Куиз Загрявка — Sites

Онлайн версията запазва интерфейса и API на локалното приложение. Работи с Vinext, TypeScript и Cloudflare D1, предоставена от Sites. Тренировките се отварят публично без вход. Банката и историята са общи. Редакции, изтриване и приемане на нови варианти на отговорите са разрешени само за собственика след вход с ChatGPT от връзката „Управление“.

## Разработка

Инсталиране: `node <sites-plugin>/scripts/install-dependencies.mjs`.
Проверки: `node scripts/test-quiz.mjs` и `node node_modules/typescript/bin/tsc --noEmit`.
Компилиране: `node <sites-plugin>/scripts/build-site.mjs`.
Локален preview: `npm run dev`. Локалният вход е симулиран само в development; production използва платформената идентичност.

За D1 schema промени използвайте `npm run db:generate`. Приложете генерираните SQL миграции към локалната база според документацията на Sites; production миграциите се прилагат при публикуване. Не променяйте вече приложени миграции.

## Данни и транзакции

`quiz_questions` и `quiz_sessions` пазят отделни JSON записи със същите идентификатори и снимки на въпросите. `quiz_meta` пази обща ревизия и маркер за импорта. Всеки запис се изпълнява в атомарен D1 batch с CHECK guard върху прочетената ревизия. При конфликт се връща HTTP 409 и целият batch се отменя, включително научените варианти на отговорите.

Началните данни се импортират еднократно от последователно SQLite резервно копие, чрез временни runtime secrets `QUIZ_IMPORT_0`, `QUIZ_IMPORT_1`, … (gzip + base64, части до 3500 знака). Данните и резервните копия не се включват в Git. След импорта тези secrets се премахват. Маркерът `imported` предотвратява повторно зареждане и възстановяване на изтрити записи. При празна база без импорт приложението връща HTTP 503, вместо да зарежда произволна банка.

Локалната и хостваната база са независими. След първоначалния импорт няма синхронизация. Не импортирайте старо копие върху работещия Site.

## Публикуване

GitHub `sites-adaptation` пази онлайн изходния код в `sites/`. За публикуването се синхронизира точно тази подпапка със служебното хранилище на Sites чрез официалния source helper. То е отделен checkout в игнорираната `outputs/` папка; не създавайте вложено Git repository в `sites/`.

Запазете `.openai/hosting.json` и неговия `project_id`. Нов проект не се създава при следваща публикация. Достъпът остава частен; GitHub push не публикува автоматично Site.

## Публичен достъп и управление

Sites трябва да е с audience `public`. Началната страница не изисква ChatGPT вход. Браузърът получава HttpOnly SameSite=Strict cookie, а bootstrap API връща CSRF token за заявките за запис. Всички заявки за промяна изискват съответстващ `X-Quiz-CSRF` header; cross-origin заявки се отхвърлят.

Публичните права позволяват четене, създаване на тренировка, автоматично запазване и предаване на отговори и кръгове. Статистиките, историята и активните тренировки са общи за групата. PUT/DELETE на въпроси, DELETE на тренировки и приемане на нови варианти изискват owner права на сървъра.

Runtime secret `QUIZ_OWNER_EMAIL` посочва потвърдения ChatGPT email на собственика. Идентичността идва от платформения вход, а не от заявено от браузъра поле. Влизането с друг ChatGPT профил не дава права за управление. Ако secret-ът липсва, управлението остава забранено. При промяна на email на собственика настройката трябва да се актуализира чрез Sites. Не включвайте стойността в Git.

Данните не се мигрират или презареждат при промяна на достъпа. Старият временен endpoint за проверка на импорта е премахнат.
